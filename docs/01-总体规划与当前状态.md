## 一、可行性结论（最重要）

**这不是"从零移植"，而是"参考适配移植"。**

OpenHarmony 6.0 LTS 源码树中**已经包含 RK3588 芯片的完整支持**：

| 已有资产 | 路径 | 说明 |
|---|---|---|
| SoC 级支持 | `device/soc/rockchip/rk3588/` | display/isp/rga/wifi/gpu 固件与驱动 |
| 板级参考移植 | `device/board/hihope/dayu210/` | 润和 HH-SCDAYU210（RK3588 EVB）标准系统 |
| 产品配置 | `vendor/hihope/dayu210/` | config.json、hdf_config、ohos.build |
| 内核 | `kernel/linux/linux-5.10`、`linux-6.6` | RK3588 标准内核 + 补丁 |

**RK3588S = RK3588 精简版**（CPU/GPU/NPU 完全相同，仅裁剪部分显示/PCIe/USB/以太网），软件层面高度兼容。

> **核心策略：把 dayu210 板级移植"克隆"为 lubancat4，再适配 LubanCat4 的 DTS、外设和分区方案。**

---

## 二、RK3588 vs RK3588S 差异（必须理解）

| 资源 | RK3588 | RK3588S |
|---|---|---|
| CPU / GPU(Mali-G610) / NPU / VPU | 4×A76+4×A55 | 相同 |
| 显示接口 | 4 路（HDMI×2/DP/eDP/MIPI DSI） | 裁剪（1-2 路） |
| PCIe / SATA / USB / GMAC | 多 | 少 |
| 引脚 | 多 | 少（封装小） |

**移植含义**：SoC 层驱动直接复用；**DTS 必须改**（pinctrl、可用控制器、板级外设）；闭源固件（GPU/VPU/NPU/ISP）与内核版本强绑定。

## 三、版本与内核策略决策（已定，勿再纠结）

| 决策点 | 结论 |
|---|---|
| OH 版本 | **v5.0.3-Release**（v6.1 因 prebuilt-sdk 机制断裂放弃，见 03 文档） |
| 内核 | **LubanCat 原厂 5.10.209 + HDF 补丁 + OH binder/access_token 移植**（方案 B） |
| 内核编译 | **不参与 OH 构建**：`build_kernel.sh` 为 no-op，boot.img 用预编译 openharmony-kernel 产物 |
| OH kernel.patch | 结构性错配，任何版本都打不上（详见 03 文档），**已弃用** |
| 未来升级 6.1 LTS | **暂缓**：先完成 5.x P4/P5 全线打通，再按 03 文档 §1.3 预检后评估（2026-08-19 已记录） |

**为什么方案 B**：dayu210 的 kernel.patch（2.4MB BSP）与 OH 主线内核结构不兼容（~63 hunk 失败），
而 LubanCat 原厂内核 BSP 已内置且在 RK3588S 上验证过。方案 B = 原厂内核 + 只叠 13 文件 hdf.patch +
OH 需要的 binder/access_token 内核特性（本阶段已全部完成）。

### 5.2 遗留问题（按优先级）

1. ~~softbus_server SIGABRT 循环~~ ✅ **已解决**（2026-08-17）：根因是 CFI 类型哈希不匹配
   （softbus_server 无条件开 CFI，而 feature 关闭时的 wifi_direct 等桩模块无 CFI）。
   修复：`dsoftbus/core/frame/BUILD.gn` 移除 softbus_server 的 CFI 配置，重编 + 重刷。
2. **网络/hdcd 配置不持久**：静态 IP、`const.security.developermode.state=true`、hdcd 均手动，重启即失。
   后续写入板级 init.cfg（顺带解决板级 cfg 安装路径问题：init cfg 装在 chipset 分区但导入路径是 /vendor/etc）。
3. **双 hdcd 实例**（手动 + init 各一个），需清理合并。
4. **hilogd 连接异常**（`HiLogAdapter_init: Can't connect to server`），hilog 查不到日志。
5. **begetctl 缺库**：`libconfigpolicy_util.z.so` 缺失（param 命令可用）。
6. **分区布局**：板上 GPT 仍是 LubanCat 8 分区，无 chip-prod/sys-prod 分区。
7. **无 UI/应用框架**：需要 UI 时把 ability_runtime/arkui/window 等加回 config.json，
   foundation 服务随之恢复（需真实 SA profile，空 profile 会被源码拒绝）。

### 5.3 已落地修复（详见 03/04 文档）

1. 内核：OH binder 扩展（BINDER_FEATURE_SET 等 3 ioctl）+ access_token 驱动 → 内核 #13
2. userdata 镜像：预建 `/data/storage/{el1..el4}`（最小配置无 storage_daemon）
3. system_mini 镜像：移除 foundation 服务（空 profile 非法）+ 启用 console shell
4. hdc：静态 IP + developer mode 参数 + `hdcd -t`
5. **USB gadget 枚举修复（2026-08-23）**：gadget 声明了 iSerialNumber 但序列号字符串为空
   → Windows 反复复位、永不 SET_CONFIGURATION（Linux 主机不受影响，回环测试可正常配置）。
   修复：cfg 写入 `serialnumber LubanCat4-0001`（仿 dayu210 拷贝 eMMC CID 的做法），
   Windows 一次枚举成功（USB_STATE=CONFIGURED）。v4 cfg 已固化到板子 `/etc/init/lubancat4-init.cfg`。
