|---|---|

#### 1.3.2 可平移 vs 不可平移

**可平移（5.0.3 成功直接带走）**

## 二、内核基线根因：kernel.patch 结构性错配（⭐核心决策）

### 2.1 现象
`kernel.patch`（2.4MB，77,169 行）打 OH linux-5.10 时横跨 20+ 文件、40+ hunk 失败：
xhci-ring.c(16/71)、option.c(7/19)、displayport.c(6/17)、pinctrl-rockchip.c(5/56)、rockchip_drm_vop.c(5/40)…

### 2.2 根因（经历两次判断修正）

1. ❌ 初判"版本时差"：board 仓库 2024-11 vs 内核 2025-03 → 方案 A（内核退 v5.0.1）。
2. ❌ 实测打脸：v5.0.1 内核上 dry-run 仍 63 hunk 失败（与 v5.0.3 几乎一样）。
3. ✅ **修正后真根因**：
   ```
   OH 的 kernel/linux/linux-5.10 ≈ 接近主线 mainline + 少量 OH 改动
   Rockchip 的 kernel.patch    = 基于 Rockchip 自己内核分支(rk-5.10.0-rkrN)的 BSP delta
   ```
   两者在 USB xhci / pinctrl / drm 等子系统**代码结构本身就不同**，
   BSP delta 硬打主线内核，**任何版本都会大面积失败**。dayu210 内核编译在这些 tag 上**一直是坏的**。

### 2.3 决策转向：方案 B（现役方案）

```
方案 B = LubanCat 原厂内核（BSP 已内置、RK3588S 验证过）
       + hdf.patch（447 行/13 文件，OH 框架钩子）
       + OH binder/access_token 内核特性（2026-08-16 已补）
       + OH defconfig + OH 用户态
```

| 对比 | kernel.patch（已弃） | hdf.patch（在用） |
|---|---|---|
| 规模 | 77,169 行 / 200+ 文件 | 447 行 / 13 文件 |
| 失败 hunk | ~63（结构性无解） | 已完全解决 |

## 四、OH binder 扩展 + access_token 移植（2026-08-16，⭐解决服务崩溃）

### 4.1 根因
OH 用户态每个服务打开 binder 后调用 `BINDER_FEATURE_SET`（`_IOWR('b',30,...)`）协商特性，
LubanCat 原厂内核 binder 只有标准 Android ioctl（≤16）→ 返回 `-EINVAL` → 服务全退
（huks/accesstoken/foundation）→ init critical 超限 → `ExecReboot panic`。

### 4.2 移植清单（openharmony-kernel，内核 #13 编译 0 错误）

| 文件 | 改动 |
|---|---|
| `include/uapi/linux/android/binder.h` | +3 结构体（binder_feature_set/access_token/binder_sender_info）+ 3 ioctl（nr 30/31/32） |
| `include/linux/sched.h` | task_struct + `u64 token/ftoken`（CONFIG_ACCESS_TOKENID 守护） |
| `drivers/android/binder_internal.h` | binder_thread + tokens/sender_pid_nr；binder_transaction + sender_tokenid/first_tokenid |
| `drivers/android/binder.c` | feature 值定义 + 事务记录 current->token + 3 个 ioctl 处理分支 |
| `drivers/accesstokenid/` | 整目录拷入（/dev/access_token_id 驱动）+ drivers/Kconfig、Makefile 挂接 |
| `include/linux/uidgid.h` | +NWEBSPAWN_UID |
| 配置 | `CONFIG_ACCESS_TOKENID=y`、`CONFIG_BINDER_SENDER_INFO=y`（Kconfig default y） |

> 注意结构差异：LubanCat 5.10.209 的 binder 结构体在 `binder_internal.h`（主线布局），
> OH 5.10.208 在 binder.c 里——移植时字段要加对位置。

### 4.3 验证
实板启动日志：`access_token_id: access_tokenid init success`，binder `-22` 消失，
samgr 正常注册 SA、boot complete。

## 六、通用排查方法论：`OHOS component (X) not found`

```
报错: OHOS component (X) not found
  ├─ X 源码在不在?  grep -l "\"name\": \"X\"" $(find . -name bundle.json)
  │   ├─ 不在 → repo 缺仓库 → manifest/repo sync
  │   └─ 在 → 版本一致吗? git describe --tags 各仓库
  │       ├─ 不一致 → repo sync -l 或重新 init
  │       └─ 都在同一 tag → 配置/prebuilt 问题
  ├─ X 属于哪个子系统? rich.json 有没有它?
  │   ├─ rich.json 漏了 → 产品配置缺口 → config.json 补子系统+X
  │   └─ X 是 sdk 特殊部件 → prebuilts_download --download-sdk
  └─ 还不通 → 看 out/<product>/error.log + build.log
```

部件类型速查：工具链类（ace_ets2bundle/ets_frontend）→ 补 config.json；Rust crate → thirdparty；SDK 类 → prebuilts。
